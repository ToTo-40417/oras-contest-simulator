# ORAS コンテストライブ戦略シミュレーター

Python 3.11以降の標準ライブラリで動く。全5種目×4ランクについて、ポケモン、5コンディション、持ち物、5ターンの予定技、NPCモデルを入力し、最終順位と得点の分布をJSONに出す。実機由来の規則を使うには `--npc cartridge` と、進行状態を表す `--contest-event-stage` または `--cartridge-roster-mode` を指定する。既定の集計方法はモンテカルロ法で、乱数分岐の独立性を仮定する。

## 実行

プロジェクトフォルダから実行する。ポケモン名と技名は日本語、または一覧にある英語IDを指定できる。

```bash
python3 -B -m oras_contest list species
python3 -B -m oras_contest list moves --species トドゼルガ
python3 -B -m oras_contest list npcs --category beauty --rank master
python3 -B -m oras_contest simulate \
  --species トドゼルガ --conditions 255 255 255 255 255 \
  --turns ほえる ギガインパクト - ほえる ギガインパクト \
  --category all --rank all --npc cartridge --contest-event-stage 15 --hall-of-fame \
  --item none --trials 10000 --trace --output walrein.json
```

コンディションの順番は、かっこよさ・うつくしさ・かわいさ・かしこさ・たくましさ。種目のIDは `cool beauty cute clever tough`、ランクは `normal super hyper master`。技は5ターン分の入力で、異なる技は最大4つ。 `-` はそのターンの予定を空欄として扱う。ギガインパクト等による行動不能は別に判定する。指定の検証では、T2が緊張で不発でもT3は空欄のまま。T4・T5の予定を繰り上げない。トドゼルガは検証入力だけにあり、本体にデフォルトのポケモンや予定技はない。

持ち物は `none`、バンダナを表す `scarf`、対応するメガストーンを表す `mega`。レックウザはガリョウテンセイを覚えていればライブアピール時にメガシンカできる。技を使わない戦術では `--known-move ガリョウテンセイ` で技枠に入れ、`--turns` には実際に出す技だけを指定する。 `scarf` で5種目を同時指定すると各種目の一致バンダナを着けた条件で比較する。同じバンダナを持たせたまま比較する場合は `--item scarf --scarf-category beauty` のように指定する。 `--seed` はPythonでの再試行を一致させる番号。既定は1。

おひろめ審査は、対象種目のコンディションに、両隣のコンディションを半分ずつ足してから小数部分を切り捨てる。対象種目と一致するバンダナなら20点を加える。ROMのおひろめ審査の計算と、隣接値の0〜255の全組み合わせ、全5種目、持ち物なしと5種のバンダナで照合した。

`--trace` は各種目・ランクの最初の試行を収録する。JSONには主人公の1～4位比率、得点分布、NPC別の出場率、出場者セット別の比率、ルチア出場時の両者の順位の組み合わせを含む。トレースの `intro_scores` は選手ごとのおひろめ点、各ターンの `hearts` はそのターンの得点、`cumulative_hearts` はターン終了時に0を下限とした累積得点。`scores` は最終順位の比較に使う得点で、おひろめ点にアピール1ハートあたり20点を加える。ROMの結果画面は内部アピール値を2倍して比較する一方、セーブ内の最新記録には2倍する前の値とおひろめ点の和を保存する。厳密な「主人公1位・ルチア4位」は両端とも同点を除外する。cartridgeモードでは単独参加の結果処理に従い、主人公が最高点で並ぶと1位になる。

## NPC設定

JSONの `unforced_scheduled_pass_pct_by_turn` は、予定が空欄のターンで実際には技を出せる状況だった試行の割合。トドゼルガの固定検証では、T2のギガインパクトが不発になっても指定どおりT3を空欄にする。この場合は反動による休みとは異なるため、この項目で確認できる。

通常の試行では `monte_carlo_95_pct_intervals` に、各順位率と「主人公1位・ルチア4位」の95% Wilson信頼区間を百分率の下限・上限で出力する。ルチア出場時に限る区間はルチア出場回数を分母とし、出場回数が0なら `null`。区間は指定モデルの試行誤差を表す。

- `early` は特殊出場者を除く。 `postgame` はカズラを候補に加える。 `challenger` はルチア初対戦を想定し、全5種目制覇後のマスターではルチア、うつくしさではミクリも固定する。 `rematch` は解禁済みのルチア、ミクリ、カズラを各レコードの出場種目に従って抽選候補に入れる。これらの進行区分はイベント観察のモデル化。`--npc cartridge --progress challenger` で出場者の上書きをしない場合は、ROMで確認した進行値17を適用する。この場合はうつくしさマスターでもルチアだけが固定で、ミクリは出場しない。
- `uniform` は4技の等重み、 `observed` は実戦観察の傾向と盤面を重みに反映し、 `competitive` は得点・妨害・ライブアピールをより強く優先する。例えば observed はルチアのかっこよさで初手りゅうのまい、かわいさで初手つめとぎ、ミクリで初手アクアリングを優遇する。倍率は仮定であり、標本から推定した頻度は入っていない。
- `--opponent Lisia --opponent Wallace --opponent Layla` で、うつくしさ・マスターのルチア・ミクリ・マスミを固定できる。1～2名だけ指定すると残りを抽選する。指定枠がある場合はイベントの強制枠を置き換える。NPC名は一覧の `trainer` を使う。
- `--parameters 設定.json` でNPC別の相対重みを差し替える。指定していない重みは1。0は抽選から外す。出場者は重み付きで重複なく3名選ぶ。技の重みを確率比として扱いたいときは `--npc uniform` を使う。

```json
{
  "roster_weights": {"Lisia": 0.25, "Wallace": 0.5},
  "move_weights": {"Lisia": {"mist": 2, "draco-meteor": 0.25}}
}
```

この例の `0.25` は重み。25%の出場率を意味しない。人数と他候補の重みによって出場率が変わる。厳密な達成率は全出場回を分母にした値と、ルチアの出場回で条件付けた値を両方出す。出場が0なら後者は `null`。

## データと検証の範囲

- 技621件、効果36種類、全国図鑑No.001～721、別習得表12フォーム、出場者69レコードを内蔵。69にはランク違いのカズラや、種目別のルチアを個別レコードとして含む。習得表は単体の習得可否の確認に使う。複数の遺伝・配布技の同時成立、入手経路、全フォームの個体差は検証対象外。
- 効果は、エキサイトとライブアピール、調子、緊張、妨害、1回防御・完全防御、コンボ、反動と離脱、先手・後手・順番のランダム化まで扱う。公開実戦観察に従い、順番変更の競合は後発優先、アピールは妨害前に16ハートで上限、連続ペナルティ時はエキサイト変動なし、反動で驚きやすい相手への半減妨害は奇数ハートも全消去とした。
- 次の挙動は未確定の実装判断。直前参照は直近にアピールを成功させた個体、緊張は各対象で独立抽選。従来モデルでは途中の行動欠落で前回技とコンボ待機を消去する。従来モデルの最終同点はランダム。エキサイトと妨害の細部には公開資料間に記述差があり、実機ログと照合する余地がある。
- NPCの条件と傾向は確認できた。この段落の傾向は仮説AIで使う。ROMとの照合結果は「全20部門で通常・特殊NPCの採点規則を使う」に記載。 `rematch` の等重み抽選では上位NPCの出場を過大評価する可能性がある。実際の攻略確率を推定するには、部門・進行段階・出場者・各ターンの手番や技を記録した実機ログが必要。

Pythonの検証を再実行する。

```bash
python3 -B -m unittest discover -s oras_contest/validation -v
```

## 出場抽選の厳密計算と対戦の総当たり

通常実行でも `scenario_roster_exact_pct` に出場者セットごとの確率、`scenario_npc_appearance_exact_pct` に各NPCが出場する確率を出す。どちらも条件に合う順序付きの出場者の組を列挙して求めるため、シードや試行回数によらない。カートリッジの出場モードではROMで照合した候補・固定枠を使い、抽選キーの順列を一様と仮定する。従来の進行プリセットでは設定した候補・固定枠・重みを使う。

`--exact --max-nodes 100000` を付けると、NPC技選択、緊張、ランダムなアピール値、同点など、モデル内で到達できる対戦分岐を列挙する。確率は分数で集計し、主要な結果はJSONの `exact_fractions` に分数表記でも出力する。上限を超えた場合はエラーになり、未完の集計を返さない。自由な4技を持つNPCが3体いる場合は分岐が急増するため、通常実行で比較し、総当たりは固定出場者と技の選択肢を絞った局面の検算に使える。

うつくしさ・マスターで、オニゴーリの予定をメロメロ、とおせんぼう、れいとうビーム、とおせんぼう、だいばくはつに固定した検算例。ルチアはしろいきり／りゅうせいぐんを等確率、ミクリはアクアテール、マスミはうずしおに固定した。

| 方法 | 主人公1位 | 主人公1位・ルチア4位 |
|---|---:|---:|
| 分岐の総当たり | 85.662194% | 2.025631% |
| 50,000試行 | 85.688% | 2.028% |

この「厳密」は指定モデル内で分岐を合算したことを指す。ROMから確認できた静的データと、実機照合が済んでいない確率・判定は、出力の `fidelity` に記載する。実機のNPCルールと乱数の偏り・相関が判明するまでは、総当たりの数値も机上の確率として扱う。

この検算で使用した設定と実行コマンド。

```bash
cat > /tmp/oras-exact-example.json <<'JSON'
{
  "move_weights": {
    "Lisia": {"dazzling-gleam": 0, "round": 0, "mist": 1, "draco-meteor": 1},
    "Wallace": {"aqua-tail": 1, "blizzard": 0, "round": 0, "aqua-ring": 0},
    "Layla": {"whirlpool": 1, "aqua-tail": 0, "surf": 0, "agility": 0}
  }
}
JSON
python3 -B -m oras_contest simulate --species オニゴーリ \
  --conditions 255 255 255 255 255 \
  --turns メロメロ とおせんぼう れいとうビーム とおせんぼう だいばくはつ \
  --category beauty --rank master --item scarf --progress rematch --npc uniform \
  --opponent Lisia --opponent Wallace --opponent Layla \
  --parameters /tmp/oras-exact-example.json --exact
```

## ROMの処理から確認した出場フィルターと技選択

コンテスト本体の処理をメモリ内で追跡した。通常の出場者決定は、NPC69レコードそれぞれにTinyMT32の32ビット出力を付け、降順に並べた後に部門・ランク・特殊出場者の可否で絞り、必要人数を先頭から採用する。あらかじめ決まった特殊出場者を入れる分岐もある。単独参加のフィルターを `--cartridge-roster-mode 0..5` で明示指定できる。この番号をゲーム内イベントやセーブ状態から決める処理とは独立している。

| モード | 単独参加で確認した特殊出場者の扱い |
|---|---|
| 0 | カズラを候補に含める |
| 1 | マスターで該当部門のルチアを第1NPC枠に固定 |
| 2 | うつくしさマスターの第1・第2NPC枠にルチアとミクリを順に固定。第3NPC枠の候補にはカズラも入る |
| 3 | ルチア、カズラを候補に含める |
| 4 | ルチア、ミクリ、カズラを候補に含める |
| 5 | 特殊出場者を候補から外す |

固定枠のほかはNPCレコードの部門・ランクに従う。確率計算では、32ビット出力の並びを一様な順列で近似する。同じ32ビット値が出たときのゲーム内の並べ替えと、プレイ時のTinyMT32初期状態の分布は、この近似に含めていない。 独立一様な32ビット出力を仮定すると、69個の値に同点が一つでも出る確率は約0.00005462%。この値を `roster_key_collision_pct_if_independent` に出力する。同点がない場合、並び順は一様になる。ROMでは出場者抽選とアピール処理が同じTinyMT32の状態を参照する。通常の `--progress` は従来のイベント推定。両設定を混ぜないよう、カートリッジモード指定時は独自の出場者固定・重み付けを受け付けない。

うつくしさマスターでは、モード1の通常NPC4人から2人を抽選するため、通常NPCごとの出場率はモデル上50%。モード2では残る1枠を通常NPC4人とカズラから抽選するため、5人それぞれ20%になる。

単独参加の受付処理は、イベント進行値16599、ランク、種目、イベントフラグ2720を使って `CallContest` の第7引数を決める。この分岐を `--contest-event-stage` で使える。たとえば `--contest-event-stage 19 --hall-of-fame` では、うつくしさマスターだけがモード2になる。分岐は全20部門、進行値0〜31、フラグの有効・無効でROMの共通イベントスクリプトと照合した。 [XAMXのORASスクリプト形式資料](https://github.com/BlastSlimey/XAMX/blob/main/what%20to%20find%20where.md) · [Pawn形式の識別子ハッシュ実装](https://github.com/SciresM/gf-pawncc/blob/master/compiler/sc6.c)

|---|---|---|
| ノーマル〜ハイパー | 8以下 | 5 |
| ノーマル〜ハイパー | 9以上 | 0 |

進行値15の結果処理では、5種目すべてのマスター優勝記録を確認する。条件成立で16へ進み、続くイベントの終了時に17となり、ルチアが固定出場する。進行値17でマスターに優勝すると18、続くイベントの終了時に19となる。進行値19から20へ進む結果処理では、うつくしさマスターの結果とイベントフラグ2720を判定する。順位による条件はなく、続くイベントの終了時に21となる。フラグ2720は殿堂入りを記録する。ROMでこのフラグを設定する処理を確認し、公開のORASフラグ表の名称と照合した。`--event-flag-2720` は `--hall-of-fame` と同じ指定として使える。 [ORASイベントフラグ表](https://www.scribd.com/document/817807502/Flags-Oras-Ja)

進行値17・19を指定した場合は、結果処理直後の進行値の分布を `post_result_event_stage_pct` に出力する。イベント終了後の進行値は上記のとおり別段階になる。

技選択では、最大6群のルールを有効フラグで選び、各技枠について条件が成立した加減点を累積する。最大点の枠を選ぶ際、同点の後続枠に遭遇するたびに、0～99の値が50未満ならその枠に乗り換える。すべて同点の場合、4枠の選択率は独立な一様な32ビット入力の下で順に12.5%、12.5%、25%、50%。均等な4択ではない。専用モジュールでこの選択段階を分離して検算した。この同点処理は `cartridge` と `cartridge-lower` で使う。

TinyMT32のPython実装は公開仕様を基にし、RFCの参照ベクトルで検証した。観察した有界抽選は、上限が65535未満なら32ビット出力との積の上位32ビット、それ以上なら剰余を使う。この規則で、上限ごとの32ビット入力個数も検算できる。ROMの実行コードやテーブルの内容を実装・成果物にコピーしていない。 [TinyMT32公開仕様](https://www.rfc-editor.org/rfc/rfc8682.html)

### 通常NPCのノーマル〜ハイパーでROM由来の採点規則を使う

`--npc cartridge-lower --cartridge-roster-mode 5` は、ノーマル・スーパー・ハイパーの通常NPCに対し、ROMの制御フローから読み取った採点規則をPythonで独立実装したモード。NPCはそのターンのアピールが始まる前に技を決める。手番中にエキサイトや妨害状況が変わっても、選択済みの技を再採点しない。候補ごとに条件付き加減点を適用し、最後に0か1の乱数加点、最高点が並んだ場合は技枠順の同点処理を行う。トレースの `planned_move` で予定技と実行技を照合できる。

```bash
python3 -B -m oras_contest simulate --species トドゼルガ \
  --conditions 255 255 255 255 255 \
  --turns ほえる ギガインパクト - ほえる ギガインパクト \
  --category all --rank hyper --cartridge-roster-mode 5 \
  --npc cartridge-lower --trials 10000 --trace
```

ROMの処理をメモリ内で照合した約12万の採点入力で、通常NPCの3ランクの乱数加点前の計算が一致した。15部門で各1万試行が完走。これは採点規則の照合であり、実機で同じターンを再生して得点・順位まで一致させた検証は別途必要。マスター、特殊NPC、乱数呼び出しの相関、進行と出場モードの対応はこのモードの検証範囲外。マスターを指定した場合はエラーになり、仮説AIへ自動で切り替えない。

### 全20部門で通常・特殊NPCの採点規則を使う

`--npc cartridge` は、ノーマルからマスターの通常NPCと、ルチア・ミクリ・カズラの候補技をROMで確認した規則に沿って採点する。通常NPCには候補ごとに0か1の乱数加点があり、特殊NPCは専用の条件付き加減点を適用する。マスターと特殊NPCを合わせた119,776件の乱数加点前の採点入力をROMの処理と照合した。

このモードではターン得点を符号付きで管理する。妨害で負になったターンは累積点を減らし、累積点の下限は0。ランダム得点技は乱数を0〜9に変換し、1・2・4・6・8ハートを約3:3:2:1:1で抽選する。ランダム得点と緊張の確率には、各結果に対応する32ビット入力の個数を使う。次ターンの手番変更は先頭・末尾の空き枠を確保し、残りの枠を得点順に並べる。手番をシャッフルする技がある場合は、それより後に指定された先頭・末尾の枠を確保し、空き枠を32ビット乱数のキー順に並べる。キーが同値のときはその比較では交換しない。確率計算ではキーを独立一様と仮定し、同値のケースも数える。

先行全員の得点を参照する技は、得点の合計が正の場合に半分を切り上げて基本点に加える。直前の成功アピールをまねる技は、その得点が正の場合に加算する。どちらも技効果での上限は16ハート。得点半減型の妨害は切り捨てで通常は最低1ハートを引く。妨害に弱い状態なら正の得点をすべて引き、得点が0以下のときは2ハート引く。ターン得点の下限は−16ハート。気合い・コンボ待機を消す妨害では、対象に消せる状態がある場合に一度きりの防御を消費する。気合いを消す妨害や通常の得点妨害は、反動などでアピールを行えなかった先行枠にも届く。直前枠を狙う妨害は、直前枠が行動できなかった場合もその枠を対象にする。技の種目が同じ相手に強い妨害は、反動で休む相手の最後に成功した技を参照する。緊張で行動できなかった相手は、この妨害の対象から外れる。

直前のアピールと出来を比べる技は、自分の基本点と気合いの合計を比較基準にする。直前の成功者のその時点の得点が基準未満なら基本点が2倍、同点なら等倍、基準を超えていれば基本点が0になり、別途気合いの点を加える。緊張や反動で行動できないターンを挟んでも、連続使用の判定には最後に成功した技を使う。コンボ待機は次ターン限りで、成立時は3ハートを加える。緊張で技が出せなければ、そのターン中はコンボ待機を参照する妨害の対象になり、ターン終了時に待機が消える。基本アピールとコンボを16ハートで上限処理してから観客の反応を加算する。トレースの `repeated` で連続使用判定を確認できる。

エキサイト依存技の基本点は、直前のゲージが0〜4の順に1・2・3・5・6ハート。後の手番ほど得点が高い技の基本点は1・2・4・6ハート。エキサイト上昇を止める技は後続の同種目技による上昇を止めるが、種目に合わない技による低下と、どの種目でも盛り上がる技の上昇は起こる。これらの処理をROMで照合した。

単独参加の最終順位は、結果処理で使う枠順の比較・交換を再現する。最高点に主人公が含まれれば主人公が勝ち、残りの最高点グループは、元の順位順に未使用の枠を抽選して並べる。抽選は32ビット値を枠数に縮小するため、3枠の場合はわずかに偏る。最高点未満の同点は比較・交換後の順で決まる。JSONの `player_first_lisia_fourth_pct` は最終順位で数え、`strict_player_first_lisia_fourth_pct` は両端に明確な得点差がある場合を数える。どちらも全試行とルチア出場時のみの割合を出力する。

次の検証例ではトドゼルガの技とターンを固定する。`--category all --rank all` で全20部門を、`--category all --rank master --road-to-lisia 3` で各マスターの突破率と各3回以内の全種目突破率を調べられる。後者では `--cartridge-roster-mode 0` を使う。

```bash
python3 -B -m oras_contest simulate --species トドゼルガ \
  --conditions 255 255 255 255 255 \
  --turns ほえる ギガインパクト - ほえる ギガインパクト \
  --category all --rank all --cartridge-roster-mode 4 \
  --npc cartridge --trials 10000 --seed 1
```

全20部門で各1万試行を完走した。出場モード0を仮定したマスター各1万試行で、トドゼルガの1位率は、かっこよさ99.99%、うつくしさ95.59%、かわいさ80.63%、かしこさ94.45%、たくましさ97.83%。部門間と再挑戦を独立と仮定すると、全種目を初回で突破する率は71.21%、各3回以内では99.25%。T3に実際には行動可能だった割合は種目順に0%、3.39%、15.73%、12.24%、8.96%で、指定どおり空欄にした場合を含む。

`--exact` が列挙する対象は指定したシナリオモデルの分岐。検証結果の確率は、出場モード、乱数分岐間の独立性を含むモデルに依存する。出場抽選・技選択・加減点・順位はROMで確認した規則を使い、確率計算では乱数分岐間の独立性を仮定する。
